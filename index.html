03 / JUNTE AS PEÇAS

O Parser conduz. O Lexer entrega.

main()recebe a expressão e imprime
→
Parser.run()cria o Lexer e confere EOF
→
parse_expression()valida a ordem e calcula
⇄
Lexer.select_next()lê caracteres e cria Token

main() passa a string para Parser.run(). O método cria um Lexer, pede o primeiro token e chama parse_expression(). A análise consulta lexer.next, usa seu valor e pede o próximo token. Cada pedido pode construir um objeto Token, que fica em next até ser substituído.

Quando não há mais PLUS ou MINUS, parse_expression() devolve sua conta. run() exige que o token restante seja EOF e devolve o resultado validado para main() imprimir. Se houver erro, uma exceção interrompe esse caminho.

A seta de ida é uma chamada; a volta entrega controle ou resultado. O Lexer reconhece as peças. O Parser decide se elas podem aparecer naquela ordem.

    @staticmethod
def run(code):
    Parser.lexer = Lexer(code)       # next começa como None
    Parser.lexer.select_next()       # prepara o primeiro token
    result = Parser.parse_expression()
    if Parser.lexer.next.type != "EOF":
        raise Exception("[Parser] Esperado EOF")
    return result

    parse_expression() exige um INT, usa seu valor e avança. Depois repete pares operador + INT enquanto houver PLUS ou MINUS. A checagem final de EOF pertence a run().

    03 / A IDEIA QUE EVITA OS BUGS

    Olhar não é avançar.

    LOOKAHEAD DE UM TOKEN

    O próximo token já está pronto.

    Na entrada de parse_expression(), lexer.next contém o próximo token ainda não consumido pelo Parser. Ao sair, essa regra continua valendo.

    lexer.next.type       # apenas consulta
lexer.select_next()   # lê e substitui next

    O nome next pode confundir: ele já foi lido pelo Lexer, mas ainda está disponível para o Parser. Consultá-lo dez vezes não move o cursor.

    Quem prepara o primeiro token?

    run(), antes de chamar parse_expression(). Sem essa chamada, next permanece None. Avançar de novo no começo de parse_expression() pula o token que já estava pronto.

    Por que os espaços agora têm um while próprio?

    Cada chamada deve entregar um token. Ela precisa atravessar todos os espaços antes de decidir o que ler. Não apague espaços da string inteira: 1 1 viraria 11 e um erro seria escondido.

    Por que conferir EOF no final?

    A expressão pode terminar deixando um token extra. Em 1 1, o primeiro número é válido, mas o segundo sobra. run() exige EOF e rejeita a entrada.

    EOF, erros e métodos estáticos

    EOF é Token("EOF", ""). Pedir o próximo token no fim continua produzindo EOF. Símbolo desconhecido gera erro [Lexer]; ordem inválida gera [Parser]. @staticmethod permite chamar os métodos sem criar um objeto Parser e sem self; é uma escolha da especificação.
